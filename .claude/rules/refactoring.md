# Refactoring Rules

## When to Refactor

- A review flagged duplication or a SOLID violation.
- The same logic is duplicated in 3+ places.
- The user asks.

## When NOT to Refactor

- **During a bug fix or feature addition** — complete the work first, refactor separately.
- **Unprompted** — working code has value; don't touch it unless asked or flagged.
- **Without a test** — say so: "Refactoring without a test is risky. Add one first via
  @test-writer." The frontend has no test runner, but it is **not** unverifiable:
  `typescript` is a devDependency (5.9.3) and `tsconfig.json` sets `strict: true` with
  `noEmit: true`, so after `pnpm install` a type check catches exactly what a component
  extraction breaks — renamed props, wrong imports, dropped types. `next build` catches
  none of it (`next.config.mjs` sets `ignoreBuildErrors: true`). Run it as
  `pnpm exec tsc --noEmit --types node`, never plain: a deprecated `@types/dompurify` stub
  raises the global `TS2688` and TypeScript then withholds every other diagnostic.

## Scope Rules

**Single file:** acceptable. Still apply `impact-awareness.md` for callers.

**`src/main.py` (414 lines, 17 endpoints):** it is the single gateway — a change reaches
every route. The `inbox_categories` block is duplicated verbatim four times
(`:75`, `:126`, `:190`, `:304`); that is the obvious candidate, and extracting it is a
**backend-only** change with no API shape impact. Verify with `pytest -v tests/` — **not**
`python run_tests.py`, which is gated on `RUN_TESTS` (`run_tests.py:7`, set only by
`docker-compose.yml:12`) and locally prints `Skipping tests` then exits 0 having run nothing.

**`src/schemas.py`:** renaming a field changes the public API, therefore the frontend, and
nothing will tell you. Grep the frontend for the JSON key before touching it. Watch the
aliases (`from` ↔ `from_sender`) in both directions.

**`app/page.tsx` (876 lines):** the app's only route and its single state container — **not
"the whole application"**. It already mounts **11 extracted components** (`:5-15`:
dashboard, folder-nav, email-list, email-actions, label-modal, filters-panel,
pagination-controls, email-content-modal, subjects-modal, filters-page, filter-modal),
~1 870 lines between them, more than twice what remains here. **Read `components/` before
extracting anything** — the presentation is largely out already. What is left is 29
`useState` declarations and the fetch handlers, so the useful split is into **hooks**, not
into new presentational components. Do it only when asked, one extraction per commit.

**`components/ui/`:** generated by the shadcn CLI. Refactoring there is thrown away by the
next `npx shadcn add`. Wrap instead. And note that 38 of those 57 files have no importer at
all — they are unused primitives, not a cleanup task.

**Cross-layer (backend + frontend):** change the backend first, then the frontend, and
commit them **together** — a split commit leaves a window where the deployed pair does not
agree, and nothing in this repo detects that.

## Commit Convention

`refactor(scope):` prefix, separate commit from the fix or feature, and explain *why* in
the message. Bilingual EN then FR, per the user's global convention — note that no commit
in this repository's history follows it yet, and every non-revert commit uses a bare
`feat:` with no scope.
